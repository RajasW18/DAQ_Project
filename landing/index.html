Common questions

Everything you need to know.

Connect the board via USB. The app uses UART at 9600 baud with ASCII line-based commands. The standalone app auto-detects COM ports — select yours from the dropdown. Simulation is the default; live serial requires explicit confirmation each time.

Yes. Simulation mode is the default for all interfaces. Table analysis, artifact generation, and AI-assisted planning work without a connected board. You can inspect firmware, generate drafts, and run analysis entirely in simulation.

In the browser workspace, drafts are stored in localStorage and never overwrite source files. In the desktop app, generated artifacts are saved as new files in your chosen directory — the app refuses to overwrite existing files. The original firmware always remains unchanged.

ForgeLab supports Groq (cloud, requires GROQ_API_KEY in your .env file) and Ollama (fully local, requires a running Ollama server with a downloaded model). The default Ollama model is llama3.2. Groq credentials never leave your local server.

The browser workspace never writes, compiles, or flashes firmware. It generates reviewable drafts only. The desktop app can trigger a PlatformIO build and upload, but only with explicit user confirmation. Generated code is always a separate draft file.

The workspace accepts .ino, .cpp, .h, .py, .json, .csv, .pdf, .md, and .txt files. PDF text extraction uses pypdf, Excel analysis uses openpyxl, and images are recorded as references. Uploaded files become part of the AI context for hardware-aware responses.

A deliberate boundary

Useful suggestions. No silent changes.

Source remains intact. The workspace labels existing files as read-only and creates separate drafts.

Hardware stays local. The browser does not flash, execute, or expose provider credentials.

Every answer has context. Ask about the actual firmware and board profile, not a generic code sample.
